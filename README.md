# STM32 OLED 驱动库 (STM32-OLED-Driver)

## 📖 项目简介
本项目是一个基于 STM32F103 标准外设库（Standard Peripheral Library）开发的 **0.96寸 OLED（SSD1306）图形驱动库**。

本项目**不依赖任何现成的第三方图形库**，完全从底层软件 I2C 时序开始手写，构建了完整的帧缓冲区（Framebuffer）架构。它提供了一套高度抽象的绘图 API，支持像素操作、区域清空、图像反色、自定义位图显示以及汉字索引显示。仓库内的 `main.c` 仅为一个用来验证驱动能力的 Demo 用例（数字时钟显示）。

## 🚀 驱动特性 (API 能力)
*   **底层时序**：基于 GPIO 的软件 I2C（开漏输出），不占用硬件 I2C 外设资源。
*   **内存架构**：内置 `framebuffer[1024]`，所有绘图操作在内存中完成，最后一次性刷新屏幕，避免频繁 I2C 通信。
*   **图形绘制 API**：
    *   `OLED_DrawPixel()`：画点（带边界防御）。
    *   `OLED_DrawBitmap()`：绘制任意大小位图（横向取模，字节高位在上）。
    *   `OLED_ClearArea()`：清空指定矩形区域，便于局部刷新。
    *   `OLED_InvertArea()`：指定区域像素反色（异或操作实现）。
    *   `OLED_ShowString_ByIndex()`：基于字库索引的任意位置汉字显示。
    *   `OLED_Refresh()`：帧缓冲区全屏刷新。
    *   `OLED_Init()`：SSD1306 标准初始化序列。

## 🛠️ 硬件与环境
*   **主控**：STM32F103C8T6 (72MHz)
*   **屏幕**：0.96寸 OLED (SSD1306, 128x64)
*   **引脚**：SCL -> PB8, SDA -> PB9
*   **环境**：Keil MDK-ARM (V5) + STM32 标准库

## 📂 代码架构
*   `oled.c` / `oled.h`：核心驱动层。包含 I2C 时序、帧缓冲区和绘图 API。
*   `OLED_Font.c` / `OLED_Font.h`：字库层。包含数字 16x32 大字号数组及自定义图标。
*   `main.c`：测试用例。演示如何在主循环中调用绘图 API 拼接数字时钟。
*   `My_timer.c` / `My_timer.h`：辅助测试。提供 1 秒定时中断，驱动 Demo 中的时间更新。

## ⚠️ 驱动层优化方向 (Code Review)
作为一个具备工业雏形的驱动，在极致性能和工程健壮性上还有提升空间：

1.  **I2C 应答检测缺失**：
    当前 `OLED_I2C_SendByte()` 直接忽略了第 9 个时钟周期的 ACK 应答。若 OLED 掉线，驱动无法感知。
    *   *优化*：在 SCL 第 9 个周期将 SDA 切为输入模式，检测到 NACK 时返回错误码，终止传输。
2.  **软件 I2C 时序过快**：
    STM32 的 GPIO 翻转速度极快，目前代码缺少微秒级延时。
    *   *优化*：在 SCL 高电平期间加入 `delay_us(1)`，确保信号稳定在 SSD1306 支持的 400kHz 极限内，或改用硬件 I2C。
3.  **`OLED_DrawBitmap()` 渲染效率**：
    该函数内部对每个像素都调用了 `OLED_DrawPixel()`，导致全屏绘制时产生大量函数压栈和重复的位运算。
    *   *优化*：在 `OLED_DrawBitmap()` 内部直接按字节操作 `framebuffer`，利用 `或运算（|=）` 直接填充字节，彻底绕过像素级函数调用。
4.  **主循环阻塞 Demo**：
    `main.c` 中的 `Delay_ms(1000)` 会导致演示程序失去响应，只能单纯刷新时间。
    *   *优化*：在定时器中断中置位 `time_flag`，主循环改为“非阻塞检测”，以便未来加入按键交互和菜单功能。
